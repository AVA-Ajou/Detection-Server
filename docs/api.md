# API

## `GET /health`

적재 상태와 각 어댑터의 계약을 돌려준다. 배포 확인과 회귀 검증의 첫 단계.

```json
{"device": "mps",
 "audio": true,
 "tasks": {"voice": {"temperature": 3.136,
                     "calibrated": true,
                     "max_text_tokens": 1024,
                     "base_model": "google/gemma-4-E2B-it"}}}
```

| 필드 | 뜻 |
|---|---|
| `device` | `cuda`(4bit) / `mps`(bf16) / `cpu`(fp32) |
| `audio` | 오디오 프로세서를 열었는가. `false`면 `/transcribe`가 501을 돌려준다 |
| `calibrated` | `false`면 `calibration.json`이 없어 보정 없이 계산 중이다 |
| `base_model` | 계약이 지정한 모델. `BASE_MODEL` 환경변수로 덮어썼다면 실제와 다를 수 있다 |

모델을 아직 올리는 중이면 `503`.

## `POST /analyze`

```json
{"text": "여보세요 서울중앙지검…", "task": "voice", "reason": false}
```

| 필드 | 기본값 | |
|---|---|---|
| `text` | (필수) | 통화 전사본. 계약의 `max_text_tokens`를 넘으면 **앞부분만** 남기고 자른다 |
| `task` | `"voice"` | `adapters/` 아래 폴더 이름 |
| `reason` | `false` | 근거 문장까지 받을지 |

```json
{"task": "voice", "risk": 93.2, "probability": 0.932,
 "stage": 3, "stage_label": "이체 지시",
 "stage_evidence": ["…지정해 드리는 상환 전용 계좌로 입금해 주시면 저희가…"],
 "reason": "\"안전계좌로 옮기셔야\"라며 이체를 준비시키고 있습니다.",
 "elapsed_ms": 12030}
```

| 필드 | |
|---|---|
| `risk` | 0~100. 온도 보정된 확률 × 100. **앱은 이 숫자를 화면에 띄우지 않는다**(아래 참고) |
| `probability` | 온도 보정을 거친 `P("예")` |
| `stage` | 진행 단계 1~3. 위험도가 70 이상일 때만. **`reason` 과 무관하게 항상 나온다** |
| `stage_label` | 단계 이름 |
| `stage_evidence` | 그 단계를 발동시킨 **원문 인용구** 목록. 규칙이 뽑으므로 검증할 수 있다 |
| `reason` | `reason: true`일 때만. **앱은 쓰지 않는다** — 아래 참고 |
| `elapsed_ms` | 서버 측 소요. 락 대기 시간이 포함된다 |

### 진행 단계

위험도와 **다른 값**이다. 위험도가 "피싱이 맞나"라면 단계는 "지금 어디까지 왔나"다.

| | | |
|---|---|---|
| 1 | 압박·유인 | 범죄 연루·구속으로 겁을 주거나, 대출·환급을 미끼로 건다 |
| 2 | 정보·계좌 | 개인정보·계좌·앱 설치를 요구한다. 돈은 아직 움직이지 않았다 |
| 3 | 이체 지시 | 송금·입금·현금 전달을 실제로 지시한다. **피해 발생 지점** |

사용자가 할 행동이 갈리는 곳은 2와 3 사이다 — 2단계까지는 준 것을 되돌리면 되고,
3단계는 몇 분 안에 돈이 나간다.

**`stage`는 모델이 아니라 규칙(`signals.py`)이 뽑는다.** 예전에는 원본 Gemma에게 생성으로
물었는데 한쪽으로 쏠렸다. 손으로 채점한 정답지 36건에서 잰 값이다.

```
             정확도    ±1 이내
  규칙        91.7%     94.4%
  생성 모델    33.3%     66.7%     ← 1단계를 한 번도 예측하지 못했다
```

재현: `python3 -m src.stage_eval --llm`

> **왜 탐지에서는 실패한 정규식이 단계에서는 통하는가** — 사기범은 "검찰"이라는 말을 피하고도
> 사칭할 수 있어서 탐지는 뚫린다(실측 43건). 그런데 돈을 받으려면 결국 계좌를 불러주고
> 입금하라고 말해야 한다. 그 말을 피하면 사기가 성립하지 않는다.

`stage`가 `null`인 경우 — 위험도가 70 미만이거나(정상 판정), 규칙이 신호를 하나도 못 찾았을
때다. **후자에 1단계를 찍지 않는다.** 증거 없이 단계를 붙이는 것은 생성 모델이 하던 실수와
같다. 피싱 전사본의 약 15%가 여기 해당하고, 앱은 이때 `주의 필요` 로 낮춰 띄운다 —
모델만 위험하다고 본 상태라는 뜻이다.

### 위험도 숫자는 화면에 내지 않는다

값이 사실상 0 아니면 100으로 갈려서 `위험도 100.0`이 "피싱임"과 같은 말이 된다. 사용자가
할 행동을 정하는 것은 점수가 아니라 단계다. 앱은 이 값을 DB와 로그에만 남긴다 —
경계선 오탐(59.8 같은 값)은 숫자로만 보이기 때문에 개발 중에는 필요하다.

### `reason`을 켜지 말 것 — 앱은 안 쓴다

| | 소요 | 하는 일 |
|---|---|---|
| 위험도 | 0.4~2초 | 순전파 한 번. 정답 자리 로짓을 읽는다 |
| 단계 | 0초 | 정규식. `stage_evidence` 로 원문 인용구까지 함께 온다 |
| 근거 | 15초 이상 | 어댑터를 끄고 160토큰 생성 |

**예전에는 단계를 받으려면 `reason: true` 를 켜야 했다.** 정규식이라 공짜인 값이 비싼 것에
딸려 있어서, 앱이 요청을 두 번 보내고 판정 한 건에 16초를 썼다. 지금은 단계가 항상 함께
나가고 앱은 요청을 **한 번만** 보낸다.

```
전       위험도 요청(1초)  →  근거+단계 요청(15초)   = 16초
현재     위험도+단계 요청(0.4~2초)                   = 2초 이하
```

근거 생성은 진단용으로 남겨뒀다. 화면에 쓰지 않는 이유는 모델이 **가장 결정적인 문구를
못 고르기 때문**이다 — 계좌번호를 부르는 대목 대신 `"통화가 녹취됩니다"` 를 뽑아오는 것을
두 번 확인했다. 규칙이 뽑는 `stage_evidence` 가 그 자리를 대신한다.

### 오류

| 코드 | |
|---|---|
| `404` | `task`에 해당하는 어댑터가 없다. `/health`로 목록 확인 |
| `422` | `text`가 비었다 |
| `503` | 모델 적재 중 |

## `POST /transcribe`

통화 음성을 글로 옮긴다. **판정은 하지 않는다** — 그건 `/analyze` 몫이다. 앱은 전사본을 받아
이벤트로 저장한 뒤 따로 `/analyze`를 부른다.

```bash
curl -s -F file=@통화.m4a -F task=voice localhost:8000/transcribe
```

| 필드 | 기본값 | |
|---|---|---|
| `file` | (필수) | multipart 오디오. `.m4a` / `.wav` |
| `task` | `"voice"` | 어떤 어댑터의 베이스를 쓸지. 전사는 **어댑터를 끄고** 하므로 결과에는 영향이 없고, 모델을 특정하는 용도다 |

```json
{"text": "안녕하세요. 저는 금융 감독원 수사관입니다…", "elapsed_ms": 9940}
```

어댑터를 끈 원본 Gemma 4가 받아적는다. 판정과 같은 가중치라 서버에 모델을 하나만 올려도 된다.

```
어댑터 ON   →  분류기 (P("예")를 읽는다)
어댑터 OFF  →  원래의 대화형 멀티모달 모델 (전사·근거 작성)
```

지시문은 `engine.TRANSCRIBE_INSTRUCTION` — `"이 음성을 한국어로 그대로 받아적어라. 요약하거나
고치지 마라."` 요약하지 말라고 못박는 이유는, 대화형 모델은 시키지 않으면 다듬거나 줄이려
들기 때문이다. 판정기에 들어갈 입력이라 원문 그대로여야 한다.

### 느리다

```
25초짜리 통화  →  맥 MPS에서 약 10초
앱 경로의 실측  →  24.7초 (에뮬레이터가 GPU를 나눠 쓰는 상태)
```

호출부는 넉넉한 타임아웃을 잡아야 한다(앱은 300초). 순전파는 락으로 직렬화되므로, 전사가
도는 동안 들어온 `/analyze`는 그만큼 기다린다.

### 형식 변환 — macOS 의존

앱이 보내는 것은 대개 `.m4a`(AAC)인데 librosa가 그 형식을 못 읽는다. macOS에 기본으로 있는
`afconvert`로 16kHz 모노 wav를 만들어 넘긴다.

```bash
afconvert -f WAVE -d LEI16@16000 -c 1 입력.m4a 출력.wav
```

**리눅스에 올릴 때 갈아끼워야 하는 유일한 지점이다** (`app._to_wav()`). ffmpeg면 된다.

### 오류

| 코드 | |
|---|---|
| `404` | `task`에 해당하는 어댑터가 없다 |
| `415` | wav로 바꾸지 못했다. 지원하지 않는 형식이거나 파일이 깨졌다 |
| `422` | 빈 파일 |
| `501` | 베이스 모델에 오디오 입력이 없다. `/health`의 `audio`가 `false`일 때 |
| `503` | 모델 적재 중 |

`501`은 Gemma 3처럼 오디오가 없는 베이스로 서버를 띄웠을 때 난다. 프로세서 적재에 필요한
`librosa`·`soundfile`·`pillow`·`torchvision`이 빠졌을 때도 같은 코드가 나온다.

## 계약 파일 — `adapters/<task>/prompt.json`

서버는 이 파일만 보고 프롬프트를 재구성한다. **학습 저장소의 코드를 참조하지 않는다.**

```json
{"base_model": "google/gemma-4-E2B-it",
 "instruction": "위 통화가 보이스피싱인지 판단하라. 예 또는 아니오로만 답하라.",
 "max_text_tokens": 1024,
 "yes": "예",
 "no": "아니오"}
```

재구성 순서다. **한 단계라도 어긋나면 에러 없이 확률만 틀어진다.**

```
① text를 토큰화해 앞 max_text_tokens 개만 남기고 다시 문자열로 decode
② f"{자른 텍스트}\n\n{instruction}" 를 user 메시지로
③ 토크나이저의 chat template 적용 (add_generation_prompt=True, tokenize=False)
④ 그 문자열을 add_special_tokens=False 로 인코딩   ← 템플릿이 <bos>를 이미 넣는다
⑤ 마지막 위치 로짓에서 yes/no 의 **첫 토큰** id 둘만 뽑아 softmax
```

`yes`/`no`는 토큰 수가 달라도 된다(`아니오`는 3토큰). 첫 토큰 id만 서로 다르면 된다.
같으면 적재 시점에 `SystemExit`으로 죽인다.

## 어댑터 추가

폴더 이름이 곧 `task` 값이 된다.

```bash
rsync -a --exclude 'checkpoint-*' ../Voice-Detection/adapter-sms/ adapters/sms/
```

**베이스가 같은 어댑터만 넣을 것.** 서버는 베이스를 하나만 올리므로, 베이스가 다르면 한쪽이
엉뚱한 모델에 붙는다 — 적재는 성공하고 **확률만 조용히 틀어진다.** `prompt.json`의
`base_model`이 서로 같은지 넣기 전에 확인한다.

폴더에 있어야 하는 것.

| 파일 | 없으면 |
|---|---|
| `adapter_model.safetensors`, `adapter_config.json` | 적재 실패 |
| `prompt.json` | 그 폴더를 어댑터로 인식하지 않는다 |
| `calibration.json` | 보정 없이 동작 (`/health`의 `calibrated: false`) |
| 토크나이저 (`tokenizer.json`, `chat_template.jinja` 등) | 적재 실패 |

학습이 끝난 어댑터에 계약만 붙이려면 학습 저장소에서:

```bash
python3 src/common.py --write-contract adapter/
```

여러 어댑터를 올려도 베이스 모델은 한 번만 적재된다. 요청마다 `set_adapter(task)`로 전환한다.

```
Gemma 4 E2B  10.0GB     ← 한 번만
voice         0.09GB
sms           0.09GB
```

## 환경 변수

| | |
|---|---|
| `BASE_MODEL` | 계약의 `base_model`을 덮어쓴다. **같은 가중치의 미러에만 쓸 것** |
| `DEVICE=cpu` | GPU를 무시하고 CPU로 강제. 디버깅용 |

`google/gemma-4-E2B-it`은 게이트되지 않아 토큰 없이 받는다(9.6GB). 이미 받아둔 미러가 있다면
`BASE_MODEL=unsloth/gemma-4-E2B-it`로 재다운로드를 피할 수 있다. 미러를 썼다면 **반드시
알려진 값으로 대조할 것** — `../Voice-Detection/docs/RESULTS.md`에 기준선이 있다.
